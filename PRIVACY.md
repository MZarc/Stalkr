# Stalkr Privacy Policy & Data Architecture

## 1. Zero-Cloud Guarantee

Stalkr is designed strictly for personal, private utility. It operates on a **zero-cloud principle**:
- **No Remote Servers**: Stalkr runs entirely on the host Android device. There is no Stalkr backend, no sync server, no relay server, and no cloud proxy.
- **Zero Telemetry / Analytics**: The application contains no Firebase Analytics, Sentry, Mixpanel, Segment, or tracking SDKs.
- **Zero Advertising**: No ad networks, measurement frameworks, or tracking pixels exist within the code.

---

## 2. Local-First Data Storage

- All account relationships, historical snapshots, and profile metadata are stored locally in `stalkr.db` inside the private application storage sandbox (`context.filesDir`).
- The database is protected by the Android application sandbox and permissions boundary.
- Notes and annotations are encrypted using AES-256-GCM backed by the Android Keystore.

---

## 3. Handling of Official Meta Exports

When a user imports an official Instagram data download (`.zip` file or unpacked directory):
1. **Local Processing**: The archive is parsed strictly in memory and temporary local app cache.
2. **Ephemeral Cache Cleanup**: Any temporary files extracted during decompression are unlinked and wiped immediately upon completion of the database import.
3. **No Secondary Transmission**: The archive contents are never uploaded or transmitted off the device.

---

## 4. Network Activity

The only outbound network requests generated by Stalkr are:
1. Direct HTTPS connections from your device to official Instagram web and API servers when an active sync is initiated.
2. Direct image requests for CDN-hosted profile avatars (when enabled).
3. If the user uses the Mock/Fixture provider, network access is completely disabled.

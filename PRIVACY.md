# Stalkr Privacy Policy & Data Architecture

## 1. Zero-Cloud Guarantee

Stalkr is designed strictly for personal, private utility. It operates on a **zero-cloud principle**:
- **No Remote Servers**: Stalkr runs entirely on the host Android device. There is no Stalkr backend, no sync server, no relay server, and no cloud proxy.
- **Zero Telemetry / Analytics**: The application contains no Firebase Analytics, Sentry, Mixpanel, Segment, or tracking SDKs.
- **Zero Advertising**: No ad networks, measurement frameworks, or tracking pixels exist within the code.

---

## 2. Local-First Data Storage

- All account relationships, historical snapshots, and profile metadata are stored locally in `stalkr.db` inside the app's private app-data directory (managed by Tauri's app-data path), protected by the Android application sandbox.
- Sessions and notes are additionally encrypted with AES-256-GCM before being written — see [SECURITY.md](SECURITY.md) for exact scope and honest limitations.

---

## 3. Handling of Official Meta Exports

When a user imports an official Instagram data download:
1. **Local Processing**: The archive is parsed on-device and its contents land only in the local database.
2. **No Secondary Transmission**: The archive contents are never uploaded or transmitted off the device.

---

## 4. Network Activity

The only outbound network requests generated by Stalkr are:
1. Direct HTTPS connections from your device to official Instagram web and API servers when an active sync (manual or scheduled) runs.
2. CDN image requests for profile avatars shown in the UI.
3. Nothing at all when running demo/fixture data (fully offline).
